# Agent Architecture

**72 canonical agent roles = 9 guilds x 8.** A role is a registry definition with
capabilities, skills, permissions, and a risk ceiling — **not** a live LLM and **not** a
model. Runtime activates only the agents a run needs (assurance planner — not yet built).

Hard separations (enforced where possible):
- **Agent != Model** — Claude/OpenAI/Gemini/local are *providers* behind a model router.
- **Agent != Skill** — e.g. the `playwright` skill belongs to `qa.web-ui-automation`.
- **Agent != Tool** — deterministic adapters live in the tool-broker.
- **Agent != Domain** — a Domain Specialist + a Domain Pack = a specialist instance.

Least-privilege invariants are baked into `schemas/agent.schema.json` and verified for every
agent by `tests/integration/agent-registry.test.ts`:
`canCloseOwnFinding`, `canSelfAuthorize`, `canExpandScope`, `canModifyPolicy`,
`canExportSecret` are all `const false`; no agent may carry the R3 risk ceiling. This encodes
separation of duties (detector is not the closure authority) and the no-self-authorization rule.

Definitions: `agents/registry/agents.json` (generated by `scripts/gen-agents.mjs`).
Legacy roles are mapped in `AGENT-ROLE-MIGRATION-MAP.md`.
